# ECHOHEARTS: REBEARTH — SEASONAL ECO-KIN & EXPANSION GOVERNANCE

**Date:** 2026-09-27  
**Status:** CANON LOCK / PRODUCTION GOVERNANCE  
**Authority:** `MASTER_PROJECT_INDEX.md` → Final Universe Consolidation → Final Terminology Lock → current Permanent Dex / Forms Registry / Historical Naming Pool

## 1. New production rule: Eco-Kin can arrive over time

The game does **not** require every approved Eco-Kin to be fully implemented at the same time.

Eco-Kin may be introduced, completed, activated, spotlighted, or expanded during:

- future development sessions;
- post-launch seasons;
- story chapters;
- regional content updates;
- event arcs;
- DLC / expansion packs;
- post-game Star Rewrite / Chrono-Rift content;
- later art, rig, animation, ecology, audio, networking, and balance passes.

This is a release-cadence rule, not permission to create uncontrolled duplicate species.

## 2. The 125-ID Permanent Dex remains the identity authority

The existing **125-ID Permanent Eco-Kin Dex** remains the current production-roster authority.

Important distinction:

- `Permanent Dex membership` = identity is authorized for the production roster.
- `Implemented` = runtime data/assets/gameplay exist.
- `Release-available` = players can actually encounter/use that identity in the current build/season.

Therefore an Eco-Kin may already belong to the 125-ID authority while remaining unreleased or incomplete until a future season.

The project does **not** need to fabricate placeholder stats, loot, art, or abilities for all remaining IDs simply to fill the table now.

## 3. Seasonal activation states

Every Permanent Eco-Kin should eventually carry a separate availability state such as:

- `RegistryLocked` — identity is approved but not production-ready;
- `InProduction` — art/data/gameplay work is active;
- `VerticalSlice` — included in a bounded proof milestone;
- `LaunchAvailable` — enabled in the launch content set;
- `SeasonalAvailable` — enabled through an authored season/update;
- `ExpansionAvailable` — enabled by an expansion/DLC package;
- `EventAvailable` — temporarily encounterable through an event without deleting its permanent identity;
- `VaultedFromRotation` — not currently encounterable but still canon;
- `Retired/Remapped` — removed from active identity use only through explicit canon governance.

Availability never changes a creature's identity by itself.

## 4. How future sessions add Eco-Kin

A future chat/session may create a creature concept, name, image, ecology idea, form, mutation, or seasonal encounter. It enters this pipeline:

`INTAKE → DUPLICATE/NAME CHECK → ORIGINALITY/IP CHECK → TAXONOMY → ESSENCE/TAGS → ECOLOGY → STORY/SEASON ROLE → FORMS/GROWTH REVIEW → ART PROVENANCE → IMPLEMENTATION → VALIDATION → RELEASE AVAILABILITY`

A chat-created name does not automatically become a new Permanent Dex ID.

## 5. Adding beyond 125 later

The current roster stays at 125 unless the user explicitly approves a versioned roster expansion.

If a future season needs a truly new permanent species beyond the existing 125, use an explicit migration such as:

- `Permanent Dex v1 = 125 IDs`;
- later approved `Permanent Dex v2 = 126+ IDs`.

A version bump must include duplicate audit, story/ecology placement, save compatibility, Bestiary/API migration, network persistence, achievements/collection behavior, and publication changes.

No season may silently create `DEX-126`.

## 6. Forms and variants remain cheaper than new permanent IDs

Seasonal content should prefer the existing identity-preserving systems when appropriate:

- Shimmer Form;
- Aurivelle Form where its parent is authorized;
- regional variants;
- corrupted / purified states;
- seasonal appearance variants;
- Growth Rite branches;
- reversible mutations/forms;
- encounter-only historical/Chrono states.

These do not consume a new Permanent Dex slot unless the resulting being is intentionally established as a distinct species through the normal governance process.

## 7. Seasonal content must not become pay-to-win

Seasonal monetization, if later approved, may support:

- cosmetics;
- housing/Sanctuary decoration;
- emotes;
- visual A.E.G.I.S. shells;
- non-stat banners/profile items;
- music/UI themes;
- other non-competitive presentation content.

The following are not automatically approved:

- paid permanent stat superiority;
- gacha ownership of sentient Eco-Kin;
- paid capture success;
- selling Eco-Kin or Eco-Egg ownership;
- paid competitive advantages;
- energy systems that block ordinary progression unless a separate business-model review explicitly approves them.

The seasonal-content rule does **not** lock Echohearts into a free-to-play or gacha business model.

## 8. Seasonal story cadence

Future Eco-Kin releases should be attached to world/story reasons whenever practical, for example:

- biome restoration reveals returning species;
- a Chrono-Rift exposes an Ancient Beast lineage;
- a new region opens through Sky Reclamation;
- migration changes after the Great Bloom;
- a faction rescue arc introduces a new partner;
- Star Rewrite reveals off-world lineages;
- a seasonal ecological phenomenon creates a reversible form.

This keeps the roster expansion connected to the world instead of functioning as disconnected content drops.

## 9. Current vertical-slice scope remains small

The funding/first-runtime vertical slice still targets a small set of exceptional Eco-Kin rather than attempting to implement the full 125 immediately.

The production priority remains:

1. prove one original humanoid + one Eco-Kin rig/body pipeline through Issue #10;
2. polish a 4–6 Eco-Kin funding slice;
3. validate Kindling, exploration, combat, ecology/restoration, save and packaging;
4. expand the roster in controlled waves afterward.
